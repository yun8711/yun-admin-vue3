# 前端权限控制说明

## 适用范围

本文说明 `rhea-fe` 项目前端现有的权限控制方式，面向需要新增页面、菜单、按钮或排查权限问题的前端开发者。

本文只描述前端侧的展示、路由注册、交互禁用和请求上下文传递。最终数据访问安全仍应以后端鉴权为准。

## 权限控制层级

当前项目的前端权限主要分为四层：

1. 路由级权限：控制用户能否访问某个页面。
2. 菜单级权限：控制顶部导航、侧边栏菜单展示。
3. 按钮/操作级权限：控制页面按钮、表格操作是否可用。
4. 接口上下文权限：请求时透传当前租户和当前菜单标识，供后端鉴权、审计或日志使用。

权限数据的核心来源是 `localStorage.loginRoutes`。本地动态路由通过 `meta.menuKey` 与后端返回的菜单权限数据匹配。

## 路由级权限

### 固定路由

固定路由定义在 `src/router/index.js` 的 `constantRoutes` 中，例如：

- `/apply`
- `/404`

固定路由不参与动态权限过滤。

### 动态路由

动态路由定义在 `src/router/async-routes/index.js` 及其子模块中。业务页面通过 `meta.menuKey` 声明权限标识。

示例：

```js
{
  path: "/metadata",
  meta: {
    title: "元数据",
    menuKey: "meta_manage",
  },
}
```

权限生成逻辑位于 `src/store/modules/permission.js`：

```js
const originRoutes = JSON.parse(localStorage.getItem("loginRoutes"));
const { mergedRoutes, allAsyncPath } = mergeRoutes(asyncRoutes, originRoutes);
```

核心过滤规则如下：

```js
if (skipMenuKey || !item?.meta?.menuKey || originItem) {
  // 允许加入最终路由
}
```

含义：

1. `skipMenuKey = true` 时跳过菜单权限校验，主要用于本地调试。
2. 路由没有配置 `meta.menuKey` 时默认放行。
3. 路由配置了 `meta.menuKey` 时，必须能在 `loginRoutes` 中找到同名 `menuKey`，否则不会加入最终路由表。

动态路由在 `src/router/routerEach.js` 的导航守卫中生成并注册：

```js
const accessRoutes = await store.dispatch("permission/generateRoutes");
accessRoutes.forEach((item) => {
  router.addRoute(item);
});
router.addRoute(finalRoute);
next({ ...to, replace: true });
```

因此，用户直接输入无权限路由地址时，该路由不会被注册，最终会进入 `* -> /404` 兜底逻辑。

## 菜单级权限

菜单不是单独请求生成的，而是来自已经过滤后的动态路由。

顶部导航读取 `src/layouts/nav-head/index.vue` 中的 `permissionRoutes`：

```js
navRoutes() {
  return this.$store.state.permission.permissionRoutes;
}
```

侧边栏读取 `src/layouts/side-bar/index.vue` 中的 `menuList`：

```js
this.sidebarRoutes = this.$store.state.permission.menuList.find(
  (x) => x.path === matched?.[0].path,
)?.children;
```

菜单层级和排序在 `src/store/modules/permission.js` 中处理：

1. `generateMenuList` 根据 `meta.parent` 组织菜单层级。
2. `sortList` 根据 `meta.serialNum` 升序排序。
3. `hidden: true` 的路由不会显示在侧边栏中，但仍可作为详情页、编辑页等子页面访问。

侧边栏项在 `src/layouts/side-bar/SidebarItem.vue` 中过滤隐藏菜单：

```js
const subMenu = this.routeInfo?.children?.filter((x) => !x?.meta?.hidden) ?? [];
```

## 按钮/操作级权限

后端返回的 `loginRoutes` 中，每个菜单可带 `btnList`。路由合并时会把后端按钮权限写入当前路由的 `meta.btnList`：

```js
btnList: originItem?.btnList ?? [],
```

页面中通过全局方法 `mDisabled(actionCode, row)` 判断按钮是否禁用。

示例：

```vue
<el-button type="primary" :disabled="mDisabled('CREATE')" @click="create">
  新增
</el-button>
```

表格操作常见写法：

```js
{
  label: "编辑",
  prop: "edit",
  disabled: (scope) => {
    return this.mDisabled("UPDATE", scope.row);
  },
  confirm: (scope) => this.edit(scope.row),
}
```

`mDisabled` 来自 `@kd/components` 的全局 mixin。本项目在 `src/main.js` 中通过以下代码注册：

```js
Vue.use(KdComponents);
```

其核心判断逻辑是：

1. 读取当前路由的 `this.$route.meta.menuKey`。
2. 读取当前路由的 `this.$route.meta.btnList`。
3. 判断 `btnList` 中是否存在匹配的 `action_mode` 或 `code`。
4. 如果存在 `ADMIN` 权限，则视为管理员操作权限。
5. 如果传入了行数据，会结合 `owner`、`owners`、`creator`、`createUser`、`createBy` 与 `localStorage.loginInfo.name` 判断数据归属。
6. 无匹配权限或异常时返回禁用。

按钮权限在项目中通常表现为“禁用按钮”，不是直接隐藏按钮。是否隐藏、是否展示、禁用提示由具体组件配置控制。

## 行级权限

部分表格操作还支持行数据自己的权限字段 `permissionTypes`。

`@kd/components` 的 `ColumnOperate` 中有如下逻辑：

```js
if (item.permission && get(scope, 'row.permissionTypes')) {
  rowDisabled = !scope.row.permissionTypes.includes(item.permission.toLowerCase());
}
```

含义是：如果按钮配置了 `permission`，并且当前行数据有 `permissionTypes`，则必须包含对应权限，否则该行按钮禁用。

因此项目中常见两类行级限制：

1. 当前登录用户是否具备当前页面按钮权限：`mDisabled("UPDATE", row)`。
2. 当前行数据是否允许该操作：`row.permissionTypes` 或业务状态判断。

常见组合写法：

```js
return this.mDisabled("UPDATE", scope.row) || this.getOperateDisabled(scope.row, item);
```

## 接口请求中的权限上下文

接口请求封装在 `src/utils/request.js`。

请求拦截器会自动写入：

```js
config.headers["tenantId"] = localStorage.getItem("tenantId") || "";
config.headers["menuKey"] = router.currentRoute?.meta?.menuKey;
```

字段含义：

1. `tenantId`：用于租户隔离。
2. `menuKey`：用于让后端知道本次请求来自哪个菜单或页面，可用于后端鉴权、日志或审计。

接口返回 `401` 时，前端会根据运行环境执行不同处理：

1. qiankun 环境：设置 `localStorage.isLogin = false`。
2. 非 qiankun 环境：提示打开主系统重新登录或刷新页面。

## 401 与 404 的区分

无权限访问和路径不存在都会先进入 `/404`，实际展示组件由 `src/views/404/index.vue` 判断。

核心逻辑：

```js
const noPermissions = storePermission.allAsyncPath.includes(redirectedFromPath);
vm.currentCom = noPermissions ? "Component401" : "Component404";
```

含义：

1. 如果访问路径存在于本地动态路由配置中，但由于权限过滤没有注册，则展示 401。
2. 如果访问路径本身不在动态路由配置中，则展示 404。

## 新增页面的接入方式

新增需要权限控制的页面时，应按以下步骤处理：

1. 在动态路由中配置 `meta.menuKey`。
2. 确认后端 `loginRoutes` 返回相同的 `menuKey`。
3. 需要展示在菜单中的路由不要配置 `hidden: true`。
4. 详情页、编辑页等非菜单页面通常配置 `hidden: true`，并复用父菜单的 `menuKey`。
5. 如需侧边栏高亮父菜单，配置 `meta.activeMenu`。
6. 如需按钮权限，在后端对应菜单下配置 `btnList`，前端用 `mDisabled("ACTION_CODE")` 判断。
7. 表格行级操作可在 `btnList.disabled` 中组合 `mDisabled`、业务状态和行数据权限。

详情页路由示例：

```js
{
  path: "detail",
  name: "ExampleDetail",
  component: () => import("@/views/example/detail"),
  meta: {
    hidden: true,
    parent: "ExampleList",
    title: "详情",
    activeMenu: "/example/list",
    menuKey: "example_manage",
  },
}
```

按钮示例：

```vue
<el-button type="primary" :disabled="mDisabled('CREATE')" @click="create">
  新增
</el-button>
```

表格操作示例：

```js
{
  label: "编辑",
  prop: "edit",
  disabled: (scope) => {
    return this.mDisabled("UPDATE", scope.row);
  },
  confirm: (scope) => this.edit(scope.row),
}
```

## 注意事项

1. 前端权限只负责页面展示和交互限制，最终数据安全必须以后端鉴权为准。
2. `skipMenuKey` 只能用于本地调试，不应在生产环境开启。
3. 没有 `meta.menuKey` 的动态路由会默认放行，新增业务页面时应谨慎省略。
4. 详情页应复用父菜单 `menuKey`，否则可能出现能看到菜单但无法进入详情页的问题。
5. 按钮权限依赖当前路由的 `meta.btnList`。如果页面跳转后路由 `menuKey` 不正确，`mDisabled` 会判断异常。
6. 请求头中的 `menuKey` 来自当前路由，路由配置错误也会影响后端侧的菜单上下文识别。
